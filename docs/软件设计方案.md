# 第一部分：软件设计方案（架构版）

## 1. 产品定位

一款面向全栈/多端开发者的 Windows 桌面端**多仓库与组件级操作编排工具**。在保留 GitHub Desktop 级别的精细版本控制体验基础上，提供「工作空间管理 + 组件自动识别 + 声明式发版流水线 + CI/CD 聚合」的进阶能力。差异化核心是**组件级抽象**（同一仓库内的 Web 前端 / API 后端 / 容器镜像被识别为独立组件，可分别提交、bump、发布）。

**MVP 边界（首发必须聚焦）**：单仓库 Git 工作台（状态 / Hunk 级暂存 / 提交 / 历史 / 回滚）+ 工作空间多仓库管理。发版流水线与 CI/CD 聚合进入 M2/M3，详见第 8 节。

## 2. 技术架构（.NET 8 + WPF 路线）

| 层 | 选型 | 关键约束（评审修订） |
|---|---|---|
| 表现层 | WPF + WPF-UI（Fluent Design，深浅色自适应） | 锁定 WPF-UI 版本号，避免 3.x API 变动；自绘控件（任务进度球、组件徽标）用 `ControlTemplate` 扩展 |
| 引擎层 | LibGit2Sharp（本地高频）+ Git CLI（网络 / 复杂） | 见 2.1 双引擎互斥约束 |
| 调度层 | 全局任务队列 | 见 2.2 失败语义 |
| 存储层 | SQLite + DPAPI | 见第 4 节存储边界 |

### 2.1 引擎层：混合边界 + 双引擎互斥（评审问题 A / 1.4-3）

**混合边界策略**：
- 高频 / 本地操作走 LibGit2Sharp（状态查询、Diff 解析、索引暂存），低延迟。
- 网络 / 复杂操作走 Git CLI（Push / Pull / Merge / Rebase / Hooks / 提交），保证兼容性与凭据安全。

**🔴 双引擎写互斥约束（必须实现）**：LibGit2Sharp 与 Git CLI 操作的是**同一个 `.git` 目录**。CLI 侧 `rebase`/`gc`/hook 脚本若与 LibGit2Sharp 的 index 写入并发，会产生 `index.lock` 冲突甚至索引损坏。因此：
- 所有针对**同一仓库**的操作（无论走哪个引擎）都先获取该仓库的 `SemaphoreSlim(1, 1)` 互斥锁——**锁内选路，而非锁外分流**。
- CLI 只读命令统一加 `--no-optional-locks`，避免与 LibGit2Sharp 的 index 写入争用。
- **Hooks 透明执行约束**：LibGit2Sharp 的 commit 路径**不会执行** `pre-commit`/`commit-msg` 等 hook。凡涉及提交的操作一律走 Git CLI，或显式加载并执行对应 hook；否则用户 hook 会静默失效（必须在开发规范中强约束）。

### 2.2 调度层：失败语义（评审问题 C）

任务对象统一实现取消 / 超时 / 重试 / 背压：
- **同一仓库写串行**、跨仓库读操作与构建操作弱并行（全局并发上限默认 4，可配置）。
- **取消**：用户点击停止 → `CancellationToken` 传播，CLI 子进程收到信号后 `kill`。
- **超时**：hung 进程看门狗，默认 10 分钟（可配置），超时标记失败并清理子进程。
- **重试**：网络类操作幂等重试（指数退避，上限 3 次）；本地操作不重试。
- **背压**：CLI 大输出走 `Channel<string>` 流式消费，禁止 `Process.StandardOutput.ReadToEnd`，避免 UI 绑定卡顿。

### 2.3 行级 / Hunk 级暂存（评审问题 B）

LibGit2Sharp 的 index API **不支持直接按行写入**。实现路径：
- **MVP（Hunk 级，必须交付）**：用 LibGit2Sharp 生成 patch，按 hunk 切片后重组 patch，以 `git apply --cached` 语义回写 index。UI 提供 Hunk 级勾选暂存与 Discard 悬浮按钮。
- **远期（行级，M3+）**：在 Hunk 基础上进一步按行切片，UI 隐藏，待 Hunk 级稳定后启用。

## 3. 核心功能域

1. **工作空间与仓库管理**：树形分组、状态总览、批量 Pull/Push 预演（Bulk Dry Run，差异化亮点）。
2. **动态组件识别**：扫描标记文件与依赖树，规则初版（初版即可用，允许手动修正并持久化）：

   | 标记文件 | 识别为组件 | 备注 |
   |---|---|---|
   | `package.json` | 前端 / JS 组件 | 递归查找根依赖 |
   | `*.csproj` / `*.sln` | .NET 组件 | |
   | `Dockerfile` | 容器镜像组件 | |
   | `pom.xml` / `go.mod` / `Cargo.toml` | 后端组件 | |
   | `pubspec.yaml` | Flutter / Dart 组件 | |

   识别结果可手动修正并沉淀为「组件地图」（持久化，见第 4 节）。

3. **版本控制工作台**：文件级 / Hunk 级暂存、组件分组提交、Hooks 透明执行（遵守 2.1 约束）、多粒度回滚（Undo / Reset / Revert）。
4. **版本发布与流水线**：
   - **版本推导**（基于 Conventional Commits）：`feat` → minor，`fix`/`perf` → patch，`!` 或 `BREAKING CHANGE:` footer → major；无规范提交则提示用户手选 Bump。
   - **多组件 bump 规则**：commit 按组件地图的**路径前缀**归属组件；跨组件 commit 触发**多组件联合 bump**，并在审阅弹窗中明确列出受影响的组件。
   - **Tag 命名**：多组件场景必须带前缀（如 `web-v1.4.2`、`api-v2.0.0`），避免同仓库内 Tag 冲突。
   - 生成可编辑 Tag 与 Release Notes，一键推送平台与 Docker Hub。
5. **CI/CD 聚合**（评审 1.4-5）：解析本地 `.github/workflows`，支持 `nektos/act` 本地模拟与 `gh cli` 远程触发 / 轮询。
   - **可选能力 + 优雅降级（必须）**：启动时探测 Docker（act 前置）与 `gh` 安装 / 登录态；不可用时**禁用**对应按钮并给出引导文案，禁止直接报错崩溃。

## 4. 数据模型与存储边界（评审问题 D，新增）

**🔴 边界原则**：Git 实时状态（分支、脏文件、Ahead/Behind）**一律不落库**——每次进入视图由引擎现查，配合 `FileSystemWatcher` 节流刷新，杜绝缓存腐化导致 UI 不可信。

SQLite（Microsoft.Data.Sqlite，WAL 模式）仅存：

```sql
workspace(id, name, sort_order)
repo(id, workspace_id, path UNIQUE, display_name, identity_profile)
component(id, repo_id, kind /*web|api|desktop|image*/, name,
          root_path, version_file, auto_detected bool, manual_override bool)
pipeline(id, repo_id, name, steps_json)
setting(key PRIMARY KEY, value_json)
```

凭据：Git 推拉凭据交给 Git Credential Manager；应用级 token（GitHub PAT / API token）用 DPAPI（`System.Security.Cryptography.ProtectedData`，CurrentUser 作用域）加密存储。

## 5. Windows 运行环境适配（评审 2-11，新增）

- **长路径（>260 字符）**：manifest `longPathAware` + `AppContext.SetSwitch("Switch.System.IO.UseLegacyPathHandling", false)`。
- **中文 / 空格路径全链路测试**；CLI 输出解析统一 `-c core.quotepath=false`，按字节读取后 UTF-8 解码防 GBK 乱码。
- **单实例互斥量**，避免多开导致 `.git` 争用。
- **未签名 exe 的 SmartScreen 提示**（首发可接受，后续考虑代码签名）。
- **自动更新**：建议引入 Velopack（Squirrel 后继）做增量更新。
- 所有 CLI 调用注入 `GIT_TERMINAL_PROMPT=0`，杜绝子进程挂起等待输入。

## 6. 性能设计（评审 4.2，新增）

- **UI 虚拟化**：历史列表、文件树、任务列表使用 `VirtualizingStackPanel`（万级提交不卡）。
- **Diff 渲染窗口化**：仅渲染可视区行；单文件 Diff 超 5000 行截断并提供「外部工具打开」。
- **仓库扫描节流**：`FileSystemWatcher` 事件 500ms 防抖合并；多仓库总览轮询间隔 ≥ 5s 且仅窗口激活时轮询。

## 7. 健壮性与安全（评审 4.3，新增）

- 日志脱敏中间件：**任何日志不得出现 token / 密码**。
- 危险操作（Reset --hard / Discard / Force Push）双确认；Discard 前自动生成 stash 快照（可恢复，对应回滚弹窗的「查看将丢失的代码差异」）。

## 8. 交付里程碑（评审 4.5，新增）

| 阶段 | 范围 | 出口标准 |
|---|---|---|
| M1 | 单仓库 Git 工作台：状态 / Hunk 暂存 / 提交 / Hooks / 历史 / 回滚 | 含中文路径仓库稳定日用 |
| M2 | 工作空间多仓库 + 组件识别 + 批量预演与执行 + 任务面板 | 10 仓库并发无死锁、可取消 |
| M3 | 发版流水线（推导 / 审阅弹窗 / 回写）+ CI/CD（gh 远程为主，act 可选）+ 行级暂存 | 全流程演示走通 |

# 第二部分：Project_Manager UI 设计文档（优化版）

## 1. 设计基准与视觉规范

- **基础框架**：WPF-UI（Fluent Design）。**本设计文档为权威规格**，Figma 设计稿需以本文为准补全（详见第 5 节异常态）。
- **布局模式**：IDE 式四区布局（顶部：全局与上下文导航；左侧：导航树；右侧：主功能区；底部：运行时控制台）。
- **色彩规范**：跟随系统深浅色。成功（绿）、警告（黄）、失败 / 冲突（红）、主强调色（蓝）。
- **字体**：系统默认 UI 字体（Segoe UI Variable 或 Microsoft YaHei UI）；控制台 / 代码区等宽字体（Cascadia Code / Consolas）。

## 2. 整体主窗口布局（修订：顶栏改为单行，评审 P5）

### 2.1 顶部导航栏（Header，单行高约 44px，评审修订）

- **左侧**：`[文件] [编辑] [设置]` 菜单。
- **中部（上下文工具栏）**：
  - **项目 / 工作空间下拉**：当前选中项目名（如 `MyApp`）；多选显示 `已选中 X 个项目`；含 `新建/打开/克隆` 与最近项目列表。
  - **分支 / 操作下拉**：当前分支名（如 `main ↓`）；含 `更新(Pull) / 提交(Commit) / 推送(Push)` 与 `新建分支/切换分支`。
- **右侧（快捷状态区）**：全局主题切换（日 / 月）、全局通知铃铛、`↑2 ↓1` 状态徽标、旋转式「全局任务进度球」（有任务时旋转，点击展开底部面板）。

> 说明：初版文档描述的「两行共 80px」已被本版单行紧凑布局取代，更贴近现代桌面工具，Figma 稿已采用此方案。

### 2.2 左侧导航区（Sidebar，宽约 250px 可拖拽）

- 顶部搜索框（带 `[扫描/刷新]` 按钮）。
- 视图切换标签：`[工作空间树] | [文件树]`。
- 主体树：组 → 仓库 → 组件；节点含项目图标、名称、脏状态点（红 / 黄）、当前分支名、并发任务小风车。

### 2.3 右侧主工作区（TabView，五个主功能页，下方内容面板）

1. **概览 (Overview)**：仓库信息卡片、组件地图卡片（组件 + 状态徽标 + Checkbox 批量操作）、快捷流水线卡片。（符合度高，保持）
2. **代码变更 (Changes)**：修订——以 **Hunk 级暂存为主**（MVP），行级暂存为 M3。
   - 左侧：按组件分组的文件树 + Checkbox。
   - 右侧上方：Diff 预览，支持 **Hunk 级勾选暂存**；右侧边缘「Discard（丢弃）」悬浮按钮（点击前自动 stash，见 7 节）。
   - 右侧下方：Summary / Description 输入框、共同作者、Amend 勾选、`[提交到 XXX 分支]`、`[提交并推送]` 勾选。
3. **历史 (History)**：修订——**分支图与 Tag 标记移至 M3+（评审 P4）**；MVP 为线性提交列表 + 选中后文件列表与详细 Diff，右键支持 Revert / Cherry-pick / 复制哈希 / 创建分支。
4. **发布 (Release)**：以第三部分「发版审阅大弹窗」为权威规格（版本推导展示 + Bump 下拉 + 目标 Tag 预览 + Markdown 编辑 + 回写版本文件勾选 + 模拟运行）。本页签为入口与结果总览。
5. **CI/CD**：Workflow 列表与关联组件；运行记录卡片；`[本地 Act 运行]`（无 Docker 时禁用 + 引导）、`[远程触发]`（未登录 gh 时引导）。

### 2.4 底部控制台面板（可折叠，Tabs：Tasks / Terminal / Log）

- **Tasks**：当前项目的运行 / 排队 / 完成 / 失败任务，含状态图标、任务名、耗时、进度条；点击某行 → Terminal 自动切到该任务实时输出流。
- **Terminal**：黑底白字等宽，多任务用颜色前缀区分（如 `[Web-Build] >`）。
- **Log**：软件自身结构化日志（脱敏后）。

## 3. 关键交互弹窗（模态，WPF-UI ContentDialog，本版为权威规格）

### 3.1 「批量操作预演」弹窗（Bulk Dry Run）
多选仓库点推送 / 更新触发。DataGrid：仓库名、状态（干净 / 脏 / 冲突）、Ahead/Behind。冲突仓库默认取消勾选并提示 `[需手动解决]`；确认后 `[执行选中项]`。

### 3.2 「发版审阅」大弹窗（Release Reviewer）
点击「生成版本与 Tag」触发。
- 左：版本信息（分析出的 Features / Fixes / Breaking）、Bump 级别下拉覆盖、目标 Tag 名（含前缀预览）。
- 右：Markdown 发布说明编辑区（所见即所得 / 源码切换）。
- 底部：`[回写版本文件到仓库]` 勾选框。
- 右下：`[取消]`、`[模拟运行]`、`[确认并推送]`。

### 3.3 「回滚确认」弹窗
右键历史选择 Reset / Revert 触发。红 / 黄警告 InfoBar，明确展示「将撤销 X 个提交；影响组件：…；是否已推送远程？」；含「查看将丢失的代码差异」展开面板（基于 Discard 前 stash 快照）。

## 4. 状态提示与通知（非阻塞）

- **InfoBar**：Git 身份冲突（黄）；分支落后远端 N 个提交建议 Pull（蓝）。
- **Snackbar**（右下轻提示）：「Docker 镜像推送成功」「代码已提交到本地（带 `[撤销]`）」。
- **微动画**：后台任务进行时，对应仓库节点旁旋转小圈，避免重复点击。

## 5. 异常态 / 空态 / 冲突态设计（评审 P6，新增，必须补全 Figma 稿）

初版仅含「理想态」，以下状态需补充设计稿：
1. **空仓库 / 未打开工作空间**：引导式空态（大图标 + 「打开 / 克隆 / 新建」入口）。
2. **合并冲突解决视图**：冲突文件列表 + 三方 Diff + 「采用当前 / 采用传入 / 手动编辑」操作。
3. **批量预演冲突行**：DataGrid 中冲突仓库的 `[需手动解决]` 高亮与禁用勾选态。
4. **任务失败详情态**：失败任务行可展开，展示错误摘要 + `[重试]` 入口 + 完整日志链接。
5. **CI/CD 能力缺失态**：未检测到 Docker 时 Act 按钮禁用并提示「请安装 / 启动 Docker Desktop」；未登录 `gh` 时提示登录引导。
6. **网络 / 凭据失败态**：Push 失败的明确原因与重新授权入口。

## 6. 设计稿 → WPF 控件映射（新增，建议落地前完成）

Figma 稿采用 web 风自绘样式，与 WPF-UI Fluent 原生控件存在差异。建议在开发前输出「设计元素 → WPF-UI 控件 / ControlTemplate」映射表，避免后期返工（如任务进度球、组件卡片、Diff 区）。
