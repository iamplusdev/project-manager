# Forge 融合 · M4 模板生态 交付说明

> 状态：**WP4.1 完成**（2026-10-23）。模板可导入、可校验、可回退；错误定位到「模板名 + 字段 + 错误码」。
> 未启动：WP4.2（版本迁移路径）、WP4.3（批量生成，前置为 G8 journal 稳定）。
> 出口门禁 G4 **前半达成**（非法模板可定位），后半随 WP4.3 押后。

---

## 1. 为什么先做 WP4.1

M1–M3 的模板能力已经"能生成"，但模板本身只能**手改 JSON**：改坏了只会看到一句"模板非法"，改好了要靠重启才生效，想退回上一版只能自己去翻文件。模板生态的门槛不在生成，而在**模板作者能不能自己把模板弄对**——这一条不解决，后面批量生成再多也没有模板可批。

---

## 2. 三层分工

| 层 | 做什么 | 位置 |
|---|---|---|
| 引擎 | 校验并在异常上给出结构化定位（`TemplateName` / `Field`） | `Scaffolding/Templates/TemplateLoader.cs`、`ScaffoldException.cs` |
| 应用 | 检查 / 导入 / 备份 / 停用，全部可无界面单测 | `Application/Templates/TemplateLibraryService.cs` |
| 界面 | 设置页模板区：清单、导入、重新加载、停用、结果横幅 | `Views/SettingsWindow.xaml(.cs)` |

界面不做任何判断，只把 `TemplateIssue.Describe()` 的结果按行渲染——错误码、模板名、字段的拼装只在应用层有一份实现，否则设置页与将来的批量生成会各写一套文案。

---

## 3. 「模板名 + 字段 + 错误码」怎么落

### 3.1 引擎侧：定位从文案里拆出来

改造前所有模板错误都走同一个 `Invalid(name, "的 structure 应是非空对象。")`：模板名进了 `Details`，字段名只活在中文句子里。界面上除了"模板「X」的 structure 应是非空对象"这句人话，机器拿不到字段，既不能筛选也不能对齐提示。

改造后分成三个构造点：

| 工厂 | 用途 | 携带 |
|---|---|---|
| `Invalid(template, field, tail)` | 字段级错误（16 处调用） | 模板名 + 字段，文案统一拼成 `模板「X」的 {field} {tail}` |
| `InvalidTemplate(template, tail)` | 定位到模板但不在字段上（模板体不是对象） | 模板名 |
| `InvalidConfig(tail, field?)` | 整份配置级（JSON 语法、空对象、版本过高） | 字段可选，**不编造模板名** |

`ScaffoldException` 新增 `TemplateName` / `Field` 两个属性；`TemplateTooLarge` 也补上了字段（`structure` / `files`）。文案前缀统一由工厂拼，避免同一种问题在不同地方措辞不同、按错误码搜不到同类。

**一条设计红线**：配置级错误（`$schemaVersion` 过高、JSON 语法错）的 `TemplateName` 必须为 `null`。填一个"看起来像个名字"的值会让界面提示用户去改一个并不存在的模板。

### 3.2 应用侧：`TemplateIssue` 与去重

```csharp
public sealed record TemplateIssue(string Code, string? Template, string? Field, string Message, bool IsWarning)
```

`Describe()` 输出可直接复制的定位串。这里有个坑：引擎文案本身已带「模板「X」的 field」前缀，如果 UI 再拼一次定位串，会得到

```
[PM-SCF-010] 模板「单体桌面工具」· readme_quickstart：模板「单体桌面工具」的 readme_quickstart 缺失或为空。
```

所以 `Describe()` 先看文案里有没有已经出现过定位信息，有就只加错误码。**定位信息宁少不重**——重复的定位串让人怀疑是不是两个问题。

### 3.3 只有第一个错误

校验在第一个错误就抛出，导入预览只显示一条。这是刻意取舍：定位到"模板名 + 字段"已经能让人改对，而收集全部错误需要把加载器改成非抛出的错误累积模式，改动面远大于收益。代价写在 §7。

## 4. 导入与回退

### 4.1 导入的四个约束

| 约束 | 理由 |
|---|---|
| 先校验，不过**一个字节都不写** | 坏配置覆盖好配置，用户就失去了回退能力——回退的前提是旧文件还在 |
| 覆盖前先 `File.Copy` 到 `templates.json.<时间戳>.bak` | 备份名带毫秒，且撞名时用序号让开（时钟精度低、时间被回拨） |
| 先写 `.tmp` 再 `File.Move(overwrite)` | 中途失败不会在用户目录留下半份 JSON |
| 导入自身视为"只检查" | 用户选中当前配置时不该自己备份自己再覆盖自己 |

### 4.2 停用，而不是删除

「停用用户配置」= 改名成 `.bak`。理由：加载器本来就会在用户配置损坏时静默回退到安装目录，但那条回退是**隐式**的——用户看不出"现在用的其实是安装目录的模板"。做成显式动作后，回退从"碰巧还能用"变成"用户知情的选择"，而且反悔时文件还在。

### 4.3 重新加载（不重启生效）

`ShellContext` 里 `Templates` 从 `init` 改成私有 set + `ApplyTemplateLoad()`：向导每次打开都读 `context.Templates`，所以替换后新建的项目立刻用新模板。设置页关闭回主壳时调 `MainViewModel.RefreshTemplateState()`，让「新建项目」的可用性与告警横幅跟着变。

## 5. 顺带修掉的缺陷：播种会把「停用」撤销

**现象**：点「停用用户配置」后横幅写"已回退到 用户配置（…\templates.json）"——它说回退了，来源却还是用户配置，文件也还在。

**根因**有两层：

1. `ReloadTemplates()` 里调了 `TrySeedUserCopy()`。停用刚把文件改名移走，重载立刻又从安装目录复制一份回来。
2. 即使重载不播种，**下次启动仍会播种**：只要用户配置不存在，就当作首次启动。于是"停用"跨不过一次重启。

**修法**：

- 重载不播种（重载是"按磁盘现状重新读"，不是首次启动）；
- `TrySeedUserCopy()` 增加历史判断：用户目录里存在 `templates.json.*.bak` 说明用户来过、且很可能是主动停用，此时**不再播种**。

顺带修掉一个更隐蔽的问题：以前每次首启都会生成一份用户副本，而用户副本优先级高于安装目录——**应用更新替换了安装目录的模板后，这份陈旧的副本会一直挡在前面**，用户永远看不到新模板。现在只有真正的首次启动才播种。

证据：截图 `output/app-tpl-disabled.png`（来源显示"安装目录"，停用按钮置灰、备份保留），以及重启后再查用户目录，`templates.json` 没有被重新生成。

## 6. 顺带修的第二个问题：截图工具把 BGRA 当 RGBA

验证时主按钮显示成橙色——而设计里是蓝色 `#0F6CBD`。把通道换成 `(0xBD,0x6C,0x0F)` 正好是橙色，说明 `GetDIBits` 给的是 BGRA，而 PNG 要 RGBA。修正后错误横幅才显示出应有的红色（`#FDE7E9`）。

这个坑值得记一笔：**颜色不对先怀疑采集工具，再怀疑设计**。当时差点去改主题令牌。

## 7. 证据

```
dotnet build                              →  0 个警告  0 个错误
tests/ProjectManager.Scaffolding.Tests    →  全部通过：223 项断言（+103）
tests/ProjectManager.Application.Tests    →  全部通过：315 项断言（+54）
```

| 组 | 断言数 | 覆盖 |
|---|---|---|
| `TemplateValidationTests`（引擎，新增） | 101 | structure / descriptions / readme_quickstart / modules / gitignore / files / naming / components 各字段的定位；配置级错误不带模板名；未知字段是警告不是错误；超限码与字段；人读文案含字段名 |
| `TemplateLibraryTests`（应用，新增） | 54 | 合法导入、覆盖前备份、**非法时不碰现有文件**、选自身只检查、读不出文件的文案、停用与二次停用、未知字段只进警告、`Inspect` 不落盘、模板清单顺序与计数、同毫秒备份不撞名、定位串去重 |
| `InvariantTests` 追加 | 2 | 留有备份时不再播种 |

**断言有效性验证**（每次都实际注入错误、确认变红、再还原）：

1. 去掉"非法则提前返回"→ 3 项变红，输出如实显示坏配置覆盖了好配置；
2. 备份撞名时禁用序号后缀 → 4 项变红（第 2/3 次导入直接失败）；
3. 为让第 2 条可复现，给 `TemplateLibraryService` 加了 `clock` 接入口——真实时钟下同毫秒几乎撞不上，靠碰运气验证不了去重逻辑。

视觉证据：`output/app-tpl-error.png`（错误横幅 + 定位串）、`output/app-tpl-imported.png`（导入成功 + 备份名）、`output/app-tpl-disabled.png`（回退到安装目录）。

## 8. 已知取舍与风险

| 取舍 | 说明 | 何时重新评估 |
|---|---|---|
| 只报第一个错误 | 改一个、再导一次，而不是一次列全 | 模板作者反馈"来回试"成本高时，改成错误累积模式 |
| 导入是**整份替换**，不是合并 | 一份文件即一份完整配置；导入会替换掉用户此前所有自定义模板 | 出现"只加一个模板"的真实需求时，加合并模式并明确冲突策略 |
| 版本过高直接拒绝，不做迁移 | `$schemaVersion > 1` 时报错并提示升级应用 | WP4.2 |
| 未知字段只告警不拦截 | 前向兼容优先；拼错键名不会让整份配置失效 | — |
| 停用不改安装目录 | 只动用户目录；安装目录随包分发且通常不可写 | — |
| 批量生成未启动 | 依赖 G8 journal（部分成功可单独重试），前置未满足 | G8 稳定后 |
