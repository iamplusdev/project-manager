# Forge 融合开发计划（阶段制）

> 版本：v1.0 · 2026-10-23
> 性质：**阶段计划**，只定义"做什么、做到什么程度算完成、谁依赖谁"，**不含工期估算**。
> 上游依据：《Forge融合方案与UI设计 v1.2》（下称"方案"）、《Forge融合方案_优化补充建议》（下称"建议"）。
> 推进方式：**出口制（Gate）**——每个阶段只有通过出口标准才进入下一阶段；不按时间推进，按证据推进。

---

## 0. 计划原则

1. **出口制而非时间制**：阶段完成的判据是"交付物 + 验收证据"，不是"时间到了"。任何阶段延期只影响下一阶段开始，不改出口标准。
2. **不可逆动作先行**：Forge 归档后等价基线无法再生，因此 S0（基线冻结）必须在一切编码之前完成（建议 P0-1）。
3. **引擎先于界面**：M1 产出零 UI 依赖的引擎，M2 才做向导。界面不得反向推动引擎语义变更。
4. **一次只开一个新面**：同一阶段内不并行引入新框架、新存储、新打包方式。
5. **变更必须回流文档**：任何偏离方案的实现，先改方案附录 B，再改代码。

---

## 1. 阶段总览

```text
S0 基线冻结 ──► M1 生成引擎 ──► M2 向导 + 注册 ──► M3 领域打通 ──► M4 模板生态（可选）
   │                │                 │                  │                 │
 Gate G0          Gate G1           Gate G2            Gate G3           Gate G4
（快照入库）    （引擎可测）      （用户可用）       （融入工作流）    （生态可扩展）
```

| 阶段 | 主题 | 关键产出 | 出口门禁 | 依赖 |
|---|---|---|---|---|
| **S0** | 基线冻结 | `tests/fixtures/forge-baseline/`（8 组快照） | G0 快照可复现 | 无 |
| **M1** | 生成引擎 | `ProjectManager.Scaffolding` + 引擎测试 | G1 单测与快照全绿 | S0 |
| **M2** | 向导 + 注册 | 主壳 + 三步向导 + 项目注册 | G2 UI 验收通过 | M1 |
| **M3** | 领域打通 | 组件识别 / 仓库清单 / `git init` | G3 工作流闭环 | M2 |
| **M4** | 模板生态（可选） | 模板导入校验 / 批量生成 | G4 可定位可重试 | M2（M3 非必需） |

> **可并行的只有**：M2 的"设置页"与 M3 的"组件白名单"设计评审可提前讨论，但实现不得早于其前置门禁。

## 2. S0 · 等价基线冻结（不可逆前置）

**目标**：在 Forge 仍可运行时，把它的输出固化为可复查的测试资产，使"行为等价"从口头承诺变成可执行断言。

**前置**：Forge 源码可运行（Python 3.13 + 依赖可复原）；PM 仓库可写。

> **状态（2026-10-23）**：✅ 已完成并入库（8 组快照 + `CASE-MATRIX.md`，8/8 确定性通过，跨用例一致）。基线是后续一切等价性断言的唯一依据，**不得重跑覆盖**。

| WP | 工作包 | 产出物 |
|---|---|---|
| WP0.1 | 复原 Forge 运行环境并记录版本（Python / 依赖 / OS），写入 `CASE-MATRIX.md` | 环境快照说明 |
| WP0.2 | 落地 8 组用例（方案 9.1）：3 模板 × {全勾, 仅顶层} + 2 组预置文件重跑 | 用例脚本/清单 |
| WP0.3 | 写快照生成器：输出 `tree.json`（路径 + 类型 + SHA256 + 占位/忽略标记）与 `files/`（逐字内容） | 生成器脚本 |
| WP0.4 | 易变内容占位化：`.bak` 时间戳、`{{date}}` 替换值统一替换为 `<TIMESTAMP>` / `<DATE>` 后再算 hash | 占位化规则 |
| WP0.5 | 确定性验证：同用例连跑两次，快照必须完全一致（时区/换行/编码不得影响） | 一致性证据 |
| WP0.6 | 写入 `CASE-MATRIX.md`：用途、初态、生成命令、复现步骤 | 用例说明文档 |

**出口门禁 G0**

- [ ] 8 组快照全部入库，目录结构符合方案 9.1；
- [ ] 在**干净环境**按 `CASE-MATRIX.md` 可复现（他人可独立跑通）；
- [ ] 同用例两次运行快照完全一致（确定性）；
- [ ] 有一人独立复核过 `files/` 内容（防止把 bug 固化成基线）。

**风险**

| 风险 | 对策 |
|---|---|
| 把 Forge 的缺陷固化为"等价基线" | 复核时逐条对照方案 4.3 的 G1–G7 语义，**发现疑似缺陷先记录、不静默接受**，并决定"等价保留"还是"修正后基线" |
| 快照含时间戳导致永远不稳定 | WP0.4 占位化必须先于 WP0.5 一致性验证 |
| Forge 环境无法复原 | 立即停止后续阶段，先解决环境（这是硬前置，不可绕过） |

## 3. M1 · 生成引擎

**目标**：交付一个零 UI / 零存储依赖、可独立单测的脚手架引擎，行为与 S0 快照等价，并具备 G8–G10 三条新增安全约束。

**前置**：G0 通过；.NET 8 SDK 可用。

> **状态（2026-10-23）**：✅ 已完成，出口门禁 G1 全部达成（8/8 快照一致、116 项断言全绿、构建零警告）。证据与偏差说明见《Forge融合_M1引擎交付说明.md》。下一步：M2。

### 3.1 工作包

| WP | 工作包 | 关键点 | 产出物 |
|---|---|---|---|
| WP1.1 | 解决方案骨架 | `ProjectManager.sln` + `Scaffolding` + `Scaffolding.Tests`；**测试项目不引用 WPF**（本身就是"零 UI 依赖"的证明） | 可构建骨架 |
| WP1.2 | 模板模型与加载 | `Template` / `ModuleOption`；`$schemaVersion` 校验；**三源优先级**（`%APPDATA%` > 安装目录 `config/` > 内置）；版本过高只读降级 | `TemplateLoader` |
| WP1.3 | 表单校验 | 名称 ≤50 / 非法字符 / Windows 保留名 / 不以点结尾；简介 ≤200；路径存在且可写 | `ProjectValidator` |
| WP1.4 | 命名派生 | `pascal` / `kebab` / `snake`；非法字符折叠规则要固定（否则快照会抖） | `NameDeriver` |
| WP1.5 | 树展开 | `structure` + 选中模块合并；扁平化；空叶子收集；`gitignore` 匹配判定 | `TreeBuilder` |
| WP1.6 | 生成主流程 | 预检 → 建目录 → 写文件 → 占位；**journal 先记后做**；失败按 journal 逆序回滚 | `ScaffoldGenerator` |
| WP1.7 | 文件注入 | `files` 映射（键支持 `{{name}}`）；4 个占位符；目标已存在则跳过 | `FileInjector` |
| WP1.8 | 文本产物 | README / structure / `.gitignore`；UTF-8 无 BOM；`.bak` 加序号 | `Documents` |
| WP1.9 | 元数据 | `.pm-scaffold.json` 写入；不加入 `.gitignore` | `ScaffoldMetadata` |
| WP1.10 | 测试套件 | 快照比对（8 组）+ 不变量（G1–G10）+ 边界表（名称 49/50/51、路径 259/260/261、保留名、emoji、结尾空格） | 测试工程 |

### 3.2 出口门禁 G1

- [ ] `dotnet build` 零警告（`TreatWarningsAsErrors`）；
- [ ] 引擎测试全绿，且**快照比对 8/8 通过**（差异能输出"新增/缺失/内容不一致"三类）；
- [ ] G1–G10 每条至少一个针对性用例（G8 需模拟"回滚中取消"无效、G9 需模拟目标已存在跳过、G10 需校验字段完整）；
- [ ] 边界表全部通过（含中文路径与超长路径的预期行为）；
- [ ] 性能预算自测达标或记录偏差（4.6 表）；
- [ ] 引擎项目**不引用** WPF / Storage / CliInterop（用项目引用关系与构建验证）。

### 3.3 风险

| 风险 | 对策 |
|---|---|
| 命名派生规则含糊，导致后续改名 | 规则在 M1 冻结并写入测试；M2 只展示不重算 |
| `gitignore` 匹配语义与 Git 不一致（`output/` vs `/output`） | 只支持"目录前缀 + 通配后缀"子集，明确写入方案；不支持正则 |
| 回滚逻辑复杂，测试难覆盖真实 IO 异常 | 引入文件系统抽象（`IFileSystem`），用内存/桩实现覆盖异常路径 |

## 7. 跨阶段质量门禁

每个工作包合入前必须同时满足，不满足不得进入下一阶段：

| 门禁 | 内容 |
|---|---|
| **构建** | 零警告；解决方案整体可构建 |

| **快照影响评估** | 任何改变产物的改动，需在提交说明中写明"快照是否变化、为何变化" |
| **文档回流** | 偏离方案处先更新方案附录 B，再改代码 |
| **评审** | 引擎与安全相关改动（回滚、`files`、路径处理）需第二人评审 |

## 8. 依赖关系与关键路径

```text
S0 ──► M1 ──► M2 ──► M3
               └──► M4（可选，可与 M3 并行）
```

- **关键路径**：S0 → M1 → M2。任一环节未过门禁，后续全部不启动。
- **M3 与 M4 无强依赖**，但共用 M2 的 Storage 与模板加载能力。
- **不可并行项**：S0 与 M1（基线未定则引擎无判据）；M2 与 M1（界面不得反向定义引擎语义）。

## 10. 阶段完成的定义（DoD）

一个阶段"完成"必须同时具备：

1. **交付物齐备**：该阶段 WP 的产出物已入库；
2. **门禁证据**：出口清单逐条有可指认的证据（测试报告、截图、命令输出）；
3. **可回滚**：本阶段改动可在不改动上游阶段产物的前提下撤销；
4. **可交接**：他人按文档可复现该阶段结果；
5. **文档一致**：方案正文与该阶段实现无未登记偏差。

## 11. 变更控制

| 场景 | 处理 |
|---|---|
| 实现发现方案不可行 | 停手 → 写"偏差说明"（现象/原因/备选）→ 更新方案附录 B → 再继续 |
| 新增需求 | 先判断属于哪个阶段；若跨阶段，进"候选池"而不塞进当前阶段 |
| 快照必须变更 | 需两人确认"这是修正而非退让"，并在 `CASE-MATRIX.md` 记录变更理由 |
| Forge 归档时机 | **G1 通过后才可归档**；归档前确认快照已入库且可复现 |
